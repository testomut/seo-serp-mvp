# Как устроено

`main.py` → `serp_mvp/pipeline.py`, дальше по шагам: `serp.py` (выдача) → `storage.py` (позиции) →
`fetch.py` (страница, email, ссылка Contact) → `classify.py` (Gemini → Claude → OpenAI, при ошибке `rules.py`) →
`storage.py` / `sheets.py` (выгрузка) → `notify.py` (Telegram/Slack). `bot.py` - пульт в Telegram.

## Данные

- **Без дублей:** позиции хранятся по ключу (дата, фраза, позиция); повторный прогон в тот же день заменяет данные
  дня, новый день добавляет историю. URL размечается один раз (повторно, только если раньше его размечали правила).
- **Топ-10:** мобильная страница Google часто показывает меньше 10 обычных результатов (реклама, блоки приложений,
  результаты, убранные по жалобам DMCA). Тогда запрашивается вторая страница; позиция = органический ранг 1-10.
  Если и так меньше 10, это видно в сводке («Fewer than 10 results») и в таблице `searches`.
- **Неудавшийся поиск** не стирает данные и не выглядит как «сайт выпал из топа»: в Positions стоит `no data`.
- **Бренды без дублей:** LLM пишет один бренд по-разному («TonyBet», «Tonybet Casino»). Перед выгрузкой
  варианты склеиваются в одно имя (из `data/brands.txt` или самое частое): 829 названий → 452 бренда.
- **Демо** (`--demo`) пишет в отдельные `data/demo.db` и `demo-results.xlsx`, не трогает таблицу и не шлёт сводку.

## Ошибки

- Ретраи с паузой для поиска, страниц и LLM. Если упал SearchApi, берётся SerpApi; если упали все - фраза
  помечается failed и повторится завтра. Если упали все фразы, прогон завершается с ошибкой (красный в GitHub).
- Ответ LLM проверяется: допустимый тип сайта, relevant строго true/false и согласован с типом, brands - список.
  Некорректный ответ не сохраняется: повтор, следующий LLM, в конце правила (их разметку LLM перепроверит завтра).
- Контакт принимается, только если найден на самой странице: email или ссылка на свой домен.
  Партнёрские переходы (`/visit/`, `/go/`, ...) и чужие домены отсекаются - пустой контакт лучше неверного.

## Ежедневный запуск

GitHub Actions (`.github/workflows/daily.yml`) в 07:00 UTC; GitHub может опоздать на несколько часов, для срочного
запуска есть Run workflow и `/run` в боте. Машина GitHub после прогона стирается, поэтому база коммитится в репозиторий.

## Безопасность ключей

Ключи не попадают в код: локально в `.env` (в `.gitignore`), для ежедневного запуска в GitHub Secrets
(в логах скрыты как `***`), для бота в переменных Render. Карта нигде не привязана, поэтому утечка ключа в худшем
случае исчерпает бесплатный лимит. Токен GitHub для бота ограничен одним репозиторием и правом запуска Actions.
